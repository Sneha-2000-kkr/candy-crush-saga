# Candy Saga — Infinite Procedural Match-3 PWA

A mobile-first, Candy Crush-style match-3 game with **no hardcoded levels**. Every level (1 to infinity), its grid shape, blockers and difficulty are generated by deterministic math and a seeded PRNG. It ships as an installable Progressive Web App and can later be packaged as an Android `.apk` with Capacitor.

## What is the project?

- **Infinite levels:** Level N always generates the exact same layout, so retrying a level gives the same board.
- **Sawtooth difficulty:** every 5th level is Hard, every 10th is a Boss, and the level right after is a Relief level.
- **Progressive features:**
  - Levels 1–5: full 8×8 grid, 5 colours, score target.
  - Level 6+: 6th colour, symmetric grid cutouts, single-layer Ice.
  - Level 12+: Honey locks.
  - Level 20+: double-layer Ice and tighter move budgets.
- **Special candies:**
  - 4-in-a-row makes a Striped candy (horizontal match → vertical stripes, vertical match → horizontal stripes).
  - L/T shapes make a Wrapped candy (3×3 explosion, twice).
  - 5-in-a-row makes a Color Bomb.
  - Special + special swaps trigger chain combos (e.g. Striped + Wrapped = 3 rows + 3 columns).
- **Mercy mechanic (adaptive difficulty):** after 2 or more failed attempts in a row, Assist Mode gives refills a 15% chance of being helpful, nudging toward natural cascades. A win resets the streak.
- **Saga map:** an infinite scrolling S-curve path whose biome changes every 15 levels (Candy Meadow → Honey Forest → Ice Glacier → Electric Galaxy).
- **Juice:** procedural vector candies, translucent ice, golden honey cages, glowing laser/lightning beams, particles, score popups, screen shake and synthesized Web Audio sounds that rise in pitch on cascades.
- **Controls:** swipe to swap. The swap fires after a 25px drag without waiting for the finger to lift, and an idle hint pulses after 4 seconds.

### Architecture

The core is strictly decoupled from rendering: `src/core/` and `src/procedural/` never import Phaser or the DOM. That keeps them pure TypeScript, so headless bots can simulate thousands of games.

```
src/core/        Types, GridEngine (gravity, cascades), MatchDetector, MoveValidator
src/procedural/  SeededRNG (Mulberry32), LevelGenerator, AdaptiveDifficulty
src/scenes/      BootScene (textures), SagaMapScene, GameScene (Phaser UI)
src/audio/       SoundSynth
src/storage/     SaveManager
tests/           core-mechanics, bot-simulator, procedural, e2e-mobile
```

The engine can record a step-by-step trace of each move (clears, specials, gravity settles). `GameScene` replays that trace as animations, so game logic and visuals stay separate.

## How testing is performed

Every change must pass three gates.

1. **Gate 1: unit and edge cases** (`tests/core-mechanics.test.ts`). Checks that 4-, L/T- and 5-matches create the exact special types, that special+special combos work, that gravity skips holes without losing or duplicating candies, that Honey blocks swaps until an adjacent match breaks it, and that a deadlocked board auto-shuffles.
2. **Gate 2: bot stress simulator** (`tests/bot-simulator.test.ts`). A greedy bot plays levels 1–200 (18,000 moves, about 5,900 cascades) and asserts:
   - no cascade reaches the depth cap of 50;
   - no null or corrupt tiles on playable cells;
   - every level starts with at least 2 valid moves;
   - Assist Mode clears measurably more than normal play.
3. **Gate 3: mobile E2E** (`tests/e2e-mobile.spec.ts`). Playwright runs against the production build at 390×844 with touch. It checks:
   - the PWA shell: locked viewport, manifest, network-first service worker;
   - the map shows Level 1 and a tap opens it;
   - real touch swipes (touchstart → touchmove past 25px → touchend) change the score;
   - the Fail and Win modals work;
   - progress survives a page reload;
   - there are zero console or page errors.

There are also unit tests for the seeded RNG, level generator and adaptive difficulty (`tests/procedural.test.ts`).

```bash
npm test        # Gate 1 + Gate 2 (Vitest)
npm run e2e     # Gate 3 (builds, serves, runs Playwright)
npm run build   # type-check + production build into dist/
npm run dev     # local dev server
```

First-time E2E setup: `npx playwright install chromium`.

## Vision: shipping to customers

The goal is a zero-maintenance game that keeps producing new content without code updates.

1. **Deploy** the `dist/` folder to Vercel or Netlify (HTTPS is required for the service worker):
   ```bash
   npm run build && npx vercel --prod
   # or: npm run build && npx netlify-cli deploy --prod --dir=dist
   ```
2. **Share the link.** The customer opens it in Chrome (Android) or Safari (iPhone) and taps *Add to Home Screen*. It installs full-screen like a native app.
3. **Silent updates.** The service worker is network-first, so every push to the host reaches installed users on their next launch. No app-store review.
4. **Endless content.** Levels, shapes, blockers, difficulty and biomes are generated mathematically, so the game never runs out of levels.
5. **Later:** package the same build as a standalone Android `.apk` with Capacitor.
